# Автотесты для сервиса `internal-0.0.1-SNAPSHOT.jar`

Набор автотестов для проверки функциональности сервиса. Реализованы на стеке Java с использованием современных инструментов тестирования и отчётности.

---

## Стек технологий

- **Язык**: Java 17
- **Тестовый фреймворк**: JUnit 5
- **HTTP-клиент для тестов**: RestAssured
- **Мокирование HTTP-ответов**: WireMock
- **Отчётность**: Allure
- **Система сборки**: Maven

---

## Быстрый старт

### 1. Запуск тестируемого приложения

Запустите JAR‑файл сервиса с необходимыми параметрами:

```bash
java -jar -Dsecret=qazWSXedc -Dmock=http://localhost:8888 internal-0.0.1-SNAPSHOT.jar
```

### Запуск тестов
```bash
mvn clean test
```

### Просмотр отчёта Allure
```bash
mvn allure:serve
```

##  Замечания:
### №1. Условия токена в задании и проверка от сервиса отличаются

**В задании:** `token` — 32 символа `[A-Z0-9]`, то есть допускаются любые заглавные латинские буквы и цифры.

**Фактически:** сервис валидирует `token` регуляркой `^[0-9A-F]{32}$`, то есть только шестнадцатеричные символы (`0-9`, `A-F`). Любая буква `G–Z` в токене отклоняется.

Пример ответа сервиса на «валидный по заданию» токен:

```json
{
  "result": "ERROR",
  "message": "token: должно соответствовать \"^[0-9A-F]{32}\""
}
```

### №2. Сервис никак не сообщает о неверном `X-Api-Key`

При неверном заголовке `X-Api-Key` сервис «зависает» — не возвращает ни ошибки, ни тела ответа.

### №3. При ошибках внешнего сервиса (4xx / 5xx) сервис «зависает»

При возврате от внешнего сервиса ошибок `4xx` и `5xx` сервис так же «зависает» — не возвращает ни ошибки, ни тела ответа.
